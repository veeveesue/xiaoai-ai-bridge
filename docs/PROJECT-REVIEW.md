# 公开前评估（2026-11-10）

结论：具备可复用 POC 的基本结构，适合以实验项目公开；尚不属于可靠的全天候语音助手。首次公开版本保持现有运行逻辑，避免把未实测的大改一起发布。

## 已具备

配置和运行数据与代码隔离；能力表驱动分流和模型能力提示；新轮次取消旧请求；只把已发送的当前回复写入六轮上下文；单实例锁；原生媒体暂停失败时不追加 AI 音频；问题候选去重存档。34 项单元测试通过，但不覆盖小米云服务和真实声音。

## 优化顺序

| 优先级 | 项目 | 当前限制与验收标准 |
|---|---|---|
| P1 | 运行健康与故障恢复 | 已补错误分类、时间戳、每3次失败重建、12次失败退出及恢复事件，附健康检查和模拟故障测试；实机断网及账号失效回归仍待验收。 |
| P1 | 原生抢话与误播 | 云端记录抵达前原生可能已发声或误点歌；接口接受暂停不能证明实际停止。需实机测普通聊天、歌名歧义、翻译和“安静”，记录残留音频。 |
| P1 | 新设备首次登录 | 现有验证来自已认证设备；SDK 日志被关闭，新账号可能缺乏完成验证的提示。需用独立配置目录完成首次认证验收。 |
| P2 | 原生与 AI 上下文共享 | 原生天气和设备动作未进入 AI 历史，AI 可能重复追问或解释错误。应提供有来源/时间的结构化事实，明确“请求接受”和“执行确认”。 |
| P2 | 长期记忆与每日对账 | 尚未实现。先补每轮结构化流水，再按日提取明确偏好、目标与事实，附来源，支持更新、删除和冲突确认；不把临时天气或模型建议当用户事实。 |
| P2 | 连续接话 | 以估时代替播完事件，可能过早或过晚。默认关闭；需实机回录、截断和无应答退出测试。 |
| P2 | 日志与隐私 | 普通日志已移除问答正文，添加私有权限、轮换及配置凭据掩码；待办仍含私人文本，外部托管日志需要单独轮换。 |
| P2 | 执行验收 | 原生提醒、设备控制需逐项确认真实结果；模型无工具时不得承诺操作成功。 |
| P3 | 分发维护 | 增加跨平台托管脚本、配置向导、兼容设备矩阵、端到端模拟和依赖更新流程。 |

## 公开范围

只复制明确允许的源码、测试、配置模板和新文档。排除旧提交历史、实机 review、原始日志、真实问题待办、账号密钥、设备缓存和本机绝对路径。依赖改为显式声明实际使用的 @mi-gpt/miot，去除不需要的完整框架依赖。
